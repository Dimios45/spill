# Commissioning the physical cell

Operator-run hardware trials have exercised Spill, but successful pill transfer
and reliable motor feedback have not been established. The measured-cell procedure
below enables geometric checks; it is not required by `--zero-shot`. Use the
[operating guide](operations.md) for the current zero-shot command and stop modes.
Do physical checks with the existing hardware stop available and the workspace clear.

1. Confirm CAN identity with Karma doctor. `can0`/`can1` enumeration can swap after
   reconnecting USB. Use stable names or explicitly configured interfaces.
2. Set all three serials in `config/local.json`. Capture intrinsics with
   `uv run spill --config config/local.json calibrate --capture-intrinsics`.
   This reads factory intrinsics; it does not solve extrinsics.
3. Measure a shared world frame, each base transform, table height, reachable
   workspace, and fixed obstacles. Measure `world_from_base` for each arm,
   `world_from_camera` for `top`, and `flange_from_camera` for each wrist. A rigid
   calibration target with known dimensions and standard hand-eye calibration
   is suitable. Record actual measurements, not estimates generated by a model.
4. Replace every template transform and intrinsic. `tool_offset` is the actual
   payload/gripper envelope endpoint in the final URDF link frame; radii must
   enclose the hardware and held objects. Capsule geometry can be conservative.
   Base mounting orientation must agree with Karma's gravity configuration;
   changing visual world transforms does not change native gravity calibration.
5. Add `measured_by`, `measured_at` (ISO date), and set calibration `verified` only
   after validating measured world points. Preserve a copy of the measured profile.
   `calibrate --check` validates shape/consistency and declarations, not accuracy.
6. Verify model profile with your authenticated Dream documentation: checkpoint ID,
   supported camera orientation/placement, sample rate, six joint zeros/signs,
   radians, gripper 1=open, and any EEF/TCP convention. Set `dream.verified` only
   after this check. No camera-role substitution or checkpoint fallback occurs.
7. For a model requiring the pose-assisted YAM profile, run
   `uv sync --locked --project dream_runtime`. Set `dream.sdk_runtime` to `isolated`
   and `dream.ik` to `{"arm":"yam","head":"joint"}` as specified by your model.
   `config/dream-yam-pose.example.json` shows this profile. The second uv environment
   isolates Dream's full library from Karma's incompatible Click/LeRobot requirements.
   Spill starts only a local SDK worker, not Dream's hardware driver. Do not start
   `dreamcli robot up` beside Karma. Both environments have committed lockfiles.
8. Run read-only doctor, then shadow mode with `--no-park`. Shadow energizes the
   arms to hold their initial pose. Inspect camera inputs, predictions, and guard
   errors. It proves neither tracking nor task success.
9. Validate home moves unloaded using the original Karma workflow. Verify Ctrl+C,
   second Ctrl+C, and Stop Now in a clear cell. Do not use a loaded cup for the
   first shutdown test.
10. Run unloaded bounded motion, then empty-cup grasp/place, then inert pill-like
    objects. Measure latency, reject rates, and tracking error before changing
    limits or enabling adaptive prefetch. If repeated guard rejection occurs,
    check conventions and pacing rather than disabling the guard.
11. Collect twenty held-out pouring trials and label actual counts. Tune prompts
    or collect corrective demonstrations based on recorded failure categories.

Camera timestamping uses host monotonic receipt time plus SDK frame sequence and
device timestamp; USB devices are not hardware synchronized. Stale frames or
excessive observed skew fail the run. Hardware exposure synchronization and depth
fusion are not implemented.

The default self-collision model is a serial-chain capsule approximation with
neighbor exclusions, not an exact mesh collision solver. Static obstacles must be
entered explicitly. Hand/object semantics are provided by Dream and Astra; unseen
obstacle detection is not a certified safety boundary.
