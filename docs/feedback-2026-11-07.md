# Feedback shutdown investigation — 2026-11-07

Run: `20261107T104500-7bfa00b6`; dataset:
`runs/20261107T104500-7bfa00b6/lerobot_v3` (951 exported frames).
The operator requested a top-down paper-cup grasp and pill transfer, using
reference run `20261107T101729-6bbb5b03`.

## What happened

Both logged Astra decisions requested execution. The shutdown was not an Astra
scene-safety pause or an API timeout. Right joint 2's feedback age crossed 250 ms;
Spill inhibited new commands. It then reached 1007 ms and triggered the existing
one-second stale-feedback fault. Other joints continued to report fresh data.
Karma de-energized in place rather than homing using untrusted joint feedback.
The native right-node log also reports stalled joint-2 telemetry. Copies of both
native logs are preserved in this run as `native-left.log` and `native-right.log`.
Linux CAN counters showed no bus errors or dropped packets; these counters cannot
prove that the application correctly parsed every incoming frame.

## Reproduced defect and fix

In Karma's `native/pi_control/src/pi_servo_dm.cpp`, the status parser discarded
any frame with byte 2 equal to `0x55`, interpreting it as a register-write reply.
But byte 2 in a status frame is the low byte of joint position. A motor at such a
position could continue replying while its cached position and timestamp stopped
updating. The fix limits that opcode check to the register CAN channel `0x7FF`.

The offline regression test iterates all 256 position low-byte values on both
master-ID and P16 status channels. Before the fix it failed specifically at
`0x55`; after the fix it passes. All 15 parser/transport tests and all 63 tests
in the native test executable passed. No robot
motion was used for these tests. Raw CAN frames were not captured in this
episode, so this defect remains a plausible explanation for its stall rather
than a conclusively established cause of that specific shutdown.

## Installation and follow-up

The fix is in the parent Karma repository; the installed native executable must
be rebuilt, even when Karma is installed as an editable Python dependency:

```bash
cd ~/karma/spill
uv sync --locked --reinstall-package karma
```

No feedback limits, motor protections, or emergency-stop behavior were relaxed.
The local Spill environment was rebuilt successfully with the command above on
2026-11-07; the installed native binary was updated. No hardware rollout was
started during this investigation.
The next supervised rollout should be checked for further `feedback_gap` events.
If they recur, retain the native logs and capture timestamped CAN frames to
distinguish missing motor replies from parsing or scheduling problems. Do not
attribute subsequent gaps to the model or increase the watchdog merely to allow
execution to continue.
